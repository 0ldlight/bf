## 契约 / Contract

- **消费字段 / Consumer field**：`FileReference` 新增 `Metadata *FileMetadata`（nil=不携带）。仍是调用方可变 DTO，无并发修改承诺；Store 绑定前按值复制快照，调用方不得在操作进行中同时改写其指针内容。Create/Update/Lookup 签名、调用方事务所有权与既有路径/内容校验不变。
  `FileReference` gains `Metadata *FileMetadata` (nil = carries none). It remains a caller-owned mutable DTO with no concurrency guarantee; the Store copies the snapshot by value before binding and callers must not mutate it concurrently with an operation. Store signatures, caller transaction ownership and the existing path/content validation are unchanged.
- **Create**：nil → 七列全 NULL（兼容旧投影与未知历史）；非 nil → 全部显式字段（含合法时间 0/负值、null actor/original 与空串；updated 写侧永不 NULL——值模型无 null updated）。
  nil → seven NULL columns (legacy projection and unknown history compatible); nonnil → every explicit field (legal zero/negative times, null actors/originals and empty strings included; the write side never has a NULL updated — the value model has no null updated).
- **Update**：nil → 语句不触碰七列（本地旧调用方兼容策略，不冒充目标完整 Node DAO 契约；本片无清空整个快照的操作）；非 nil → 同一条参数化 UPDATE 原子替换七列（包括替换为 NULL）。保留 id+file 守卫、0 行不转创建、无重试/提交。
  nil → the statement leaves the seven columns untouched (an explicit local legacy-caller policy, not a claim about the target's full Node DAO; this slice adds no snapshot-clearing operation); nonnil → one parameterized UPDATE atomically replaces all seven (including with NULL). The id+file guard, zero-row no-create and no-retry/no-commit behavior are retained.
- **Lookup**：追加七列。全 NULL → `Metadata` nil（与显式零值快照不同）；created+modified 已知 → 独立分配快照，updated NULL 映射 0（对齐所选目标读取器 getLong/wasNull 边界）；其余部分形状返回固定 stageLookup 文案，Unwrap 保留 `ErrInvalidReference`，永不回显行值。Kind 检查先于元数据处理（畸形文件夹行仍 `ErrNotFile`）。actor 经 NewActor（存量超 64 码元行读取侧缩写），original 恢复可空 UTF-16；不逆推入库前的孤立代理项。时间完整保留 int64 范围，无时钟/回退/排序检查。
  Lookup appends the seven columns. All NULL → nil `Metadata` (distinct from an explicit zero snapshot); created+modified known → an independently allocated snapshot with a NULL updated mapping to 0 (matching the selected target reader's getLong/wasNull boundary); any other partial shape returns the fixed stageLookup text preserving `ErrInvalidReference` under Unwrap, never echoing row values. The kind check precedes metadata handling (a malformed folder row still yields `ErrNotFile`). Actors pass through NewActor (stored rows above 64 units abbreviate read-side) and originals rebuild as nullable UTF-16; pre-insert lone surrogates are not reconstructed. Times keep the full int64 range with no clock/fallback/ordering checks.
- **私有编解码 / Private codec**（postgres 包内，无新导出）：可空 []uint16 → nil 或 UTF-8 字符串；有效代理对正常编码、每个不成对代理码元为 ASCII `?`（0x3f，对齐所选参数编码边界的直接观察；标准库 `utf16.Decode` 的 U+FFFD 行为不是本边界契约）、字面 U+FFFD 保持、nil ≠ 空、NUL 逐字送达由数据库裁决。无 Go 侧长度/十六进制/trim/大小写预检——VARCHAR(1024) 字符计数、尾部空格截断与原生错误（超长 22001、NUL 22021）决定；读侧仅按有效 UTF-8 重建。无 fmt/JSON/Stringer 新导出，无通用编解码框架。
  Inside the postgres package with no new exports: nullable []uint16 → nil or a UTF-8 string; valid pairs encode normally, every unpaired surrogate unit becomes ASCII `?` (0x3f, matching the direct observation at the selected parameter-encoding boundary — the standard library's `utf16.Decode` U+FFFD behavior is NOT this boundary's contract), a literal U+FFFD stays, nil ≠ empty, and NUL goes to the database verbatim. No Go-side length/hex/trim/case pre-checks — VARCHAR(1024) character counting, trailing-space truncation and native errors (overlong 22001, NUL 22021) decide; the read side rebuilds from valid UTF-8 only. No new fmt/JSON/Stringer exports and no generic codec framework.

## 模式与迁移 / Schema and migration

- `schema.sql` 升为 **v2**：v1 基础上新增 created/modified/updated BIGINT、created_by/modified_by VARCHAR(64)、sha1_original/md5_original VARCHAR(1024)——全部可空、无 DEFAULT——加 `nodes_metadata_shape` CHECK（七列全 NULL **或** created+modified 非 NULL，updated 可 NULL）。"全 NULL 分支"是既有 v1 行的显式本地未知历史迁移策略，必须区别于目标全新 DDL 的 created/modified NOT NULL。
  `schema.sql` becomes **v2**: v1 plus created/modified/updated BIGINT, created_by/modified_by VARCHAR(64) and sha1_original/md5_original VARCHAR(1024) — all nullable, no DEFAULT — plus the `nodes_metadata_shape` CHECK (all seven NULL **or** created+modified non-NULL, updated may be NULL). The all-NULL branch is the explicit local unknown-history policy for existing v1 rows and must stay distinct from the target fresh DDL's NOT NULL created/modified.
- `MetadataUpgradeSQL` / `MetadataDowngradeSQL` 由独立 SQL 文件嵌入，仅供可信运维/测试在自有事务中显式执行；**Store/启动从不执行任何 DDL**，无版本表/迁移引擎/回填/导入/部署。升级是单条 ALTER（加七列+约束）；重复执行以 42701 失败，绝不静默吞掉模式漂移；`CREATE TABLE IF NOT EXISTS` 不视作升级。
  `MetadataUpgradeSQL` / `MetadataDowngradeSQL` embed from dedicated SQL files for explicit trusted operator/test execution inside their own transactions; **the Store/startup never executes DDL**, with no version table, migration engine, backfill, import or deployment. The upgrade is a single ALTER (seven columns plus the constraint); a repeat fails with 42701 instead of silently swallowing schema drift, and `CREATE TABLE IF NOT EXISTS` is not an upgrade.
- **回退优先回滚二进制、保留附加列**（旧投影使用显式列清单，写入不覆盖新元数据）。物理 `MetadataDowngradeSQL` 是单一原子 DO 语句，全部 fail-closed 且不改任何全局/会话配置：仅限 READ COMMITTED（其他隔离以固定 SQLSTATE 25000 拒绝——旧快照可能漏看取锁前刚提交的行）；取 ACCESS EXCLUSIVE 表锁后再检查（保证看到取锁前全部已提交行）；启用 RLS 的表以固定 55000 拒绝（pg_class.relrowsecurity，不依赖策略恰好隐藏行）；任何行的七个新列有任何非 NULL 值以固定 55000 拒绝，**绝不自动清空数据**；最后仅删约束与七列。任何守卫失败时整个语句回滚，无部分删列；不改权限/RLS 策略。表名沿用受信任 search_path 契约（非模式限定）。
  **Prefer rolling back the binary while keeping the added columns** (legacy projections use explicit column lists and never overwrite the new metadata). The physical `MetadataDowngradeSQL` is one atomic DO statement, fail-closed throughout and changing no global/session configuration: READ COMMITTED only (other isolation levels rejected with the fixed SQLSTATE 25000 — an older snapshot could miss rows committed just before the lock); the ACCESS EXCLUSIVE table lock is taken BEFORE the checks (so they observe every row committed before the lock); an RLS-enabled table is refused with the fixed 55000 (pg_class.relrowsecurity, never relying on policies happening to hide rows); any nonnull value among the seven new columns on any row refuses with the fixed 55000 and **data is never auto-cleared**; finally only the constraint and the seven columns drop. Any guard failure rolls the whole statement back with no partial column removal; no privileges or RLS policies change. Table names follow the trusted search_path contract (unqualified).

## 验证 / Verification

单元（`-race`，不触库）：编解码边界表（nil≠空、有效/孤立/反序代理、字面 U+FFFD/'?'、NUL、混合）、读侧解回（空串非 nil 空、星面对、往返）、actor 读取侧 64 码元缩写、nil/非 nil 七参数绑定、行形状分类（全 NULL / created+modified / 全七列 / 七种部分形状 → 有界错误）。真实 PostgreSQL 17.10 门禁（既有夹具，18 组场景）：见提交说明与[事务内文件引用](NODE-REFERENCES.md)；含全新 v2 目录断言与精确冻结 v1 DDL 的显式升级（两者均以 format_type 逐列核对 bigint×3/varchar(64)×2/varchar(1024)×2 的精确类型与宽度）、两个 original 各自的 1024 emoji 完整写入回读/1025 以 22001 拒绝/尾部空格截断边界、旧投影 INSERT/UPDATE 兼容、升级事务回滚、重复升级 42701、全 NULL down 保留行、有数据 down 拒绝且无损、非 READ COMMITTED（25000）与 RLS（55000）拒绝、以及取锁等待后仍能看到刚提交元数据的确定性阻塞回归（pg_stat_activity wait_event + pg_blocking_pids 精确阻塞者证据，不依赖睡眠时长断言）。行为 RED→GREEN 证据（对 `utf16.Decode` U+FFFD 错误基线、忽略元数据 Store 基线与 v1 fresh 基线的真实失败，及修正后的通过）归档于私有任务目录；根复验证明的 md5_original 宽度缺口已按处方补齐（变异 md5_original=VARCHAR(32) 现在同时被长度边界与目录类型断言捕获，先前通过证据保留）。
Unit (`-race`, no DB): the codec boundary table (nil≠empty, valid/lone/reversed surrogates, literal U+FFFD/'?', NUL, mixes), read-side decoding (nonnil empty, astral, round trip), read-side actor abbreviation to 64 units, nil/nonnil seven-argument binding, and row-shape classification (all NULL / created+modified / all seven / seven partial shapes → bounded errors). Real PostgreSQL 17.10 gate (existing fixtures, 18 scenario groups): see the commit message and [transaction-scoped file references](NODE-REFERENCES.md); coverage includes fresh v2 catalog assertions and the explicit upgrade over the exact frozen v1 DDL (both pinning the exact format_type column by column — bigint×3, varchar(64)×2, varchar(1024)×2), each original's own 1024-emoji full-write readback / 1025 rejected with 22001 / trailing-space truncation boundary, legacy-projection INSERT/UPDATE compatibility, upgrade-transaction rollback, repeated upgrade 42701, all-NULL downgrade keeping rows, populated downgrade refused without loss, non-READ-COMMITTED (25000) and RLS (55000) refusals, and the deterministic blocking regression proving a lock-waiting downgrade still sees freshly committed metadata (pg_stat_activity wait_event plus pg_blocking_pids naming the exact blocker, no sleep-based assertions). Behavioral RED→GREEN evidence (real failures against the `utf16.Decode` U+FFFD wrong baseline, the metadata-ignoring Store baseline and the v1 fresh baseline, then the passing runs) is archived in the private task directory; the md5-original width gap proven by the root's replay is closed per its remedy (mutating md5_original to VARCHAR(32) is now caught by both the length boundary and the catalog type assertion, with the prior pass evidence retained).

## 边界 / Boundaries

- 历史数据库探针的事实限定：46 组参数输入/440 断言针对真实 PostgreSQL 17.10 临时库 + 打包 JDBC 驱动 + 选定 DDL（显式 extended/stringtype=varchar/prepareThreshold=1/UTF8 profile）的直接观察；未执行原版应用 DAO/服务/HTTP，不宣称原版安装库或其生效驱动配置相同。本页只引用其结论，不复制原始资料。
  The historical database probe is qualified: 46 parameter inputs / 440 assertions were direct observations against a real PostgreSQL 17.10 disposable database with the packaged JDBC driver and the selected DDL under an explicit extended/stringtype=varchar/prepareThreshold=1/UTF8 profile; the original application's DAO/service/HTTP stack never ran, and no claim is made about the original installed database or its effective driver configuration. This page cites those findings without copying raw material.
- 升级/回退未含生产锁时长/规模基准；上线前需具体环境执行计划。无自动 DDL、版本表、回填、跨库迁移、生产执行、权限变更或 Fern 变更；保存编排、分配器与 HTTP 面仍属后续切片。
  No production lock-duration/scale benchmark accompanies the upgrade/downgrade; a concrete environment execution plan precedes rollout. No auto-DDL, version table, backfill, cross-database migration, production execution, privilege change or Fern change; save orchestration, the allocator and any HTTP surface remain later slices.
- 2026-10-23 独立复验：46 组已冻结参数参考、1,029 项真实 PostgreSQL Store/迁移断言通过；另有 68,338 组打包 JDBC 参数编码/NULL 参考与 Go 一致（不是 68,338 组数据库调用）。生产源码以 SHA-256 绑定到复验归档，测试和文档强化不改变生产实现。三项隔离变异证明永久回归能检出 original 宽度缩减、只删一列及移除 RLS 守卫；后两项保留修正前错误通过与修正后失败的同一变异证据。RLS 拒绝单独使用七列全 NULL 的合法行，避免与有数据拒绝的相同 SQLSTATE 互相掩盖。
  Independent replay on 2026-10-23 passed 46 frozen parameter references and 1,029 real PostgreSQL Store/migration assertions; a separate 68,338-case packaged-JDBC parameter-encoding/NULL corpus matched Go (not 68,338 database calls). Production sources are SHA-256-bound to the replay archive; regression and documentation strengthening leave the production implementation unchanged. Isolated mutations show the permanent regressions detect a narrowed original column, partial column removal and a missing RLS guard; the latter two retain the same mutation passing before the assertion repair and failing afterward. The RLS refusal uses a valid all-seven-NULL row to separate it from the populated-data guard sharing its SQLSTATE.
- 共享检查与真实 PostgreSQL 的完整门禁以审查 PR 精确提交的 CI 作业为准。远程 port-forward 全量运行超过原有五分钟上限的失败记录保留，未调高门禁、跳过测试或把超时登记通过；成功的聚焦运行不代替完整门禁。
  The shared check and full real-PostgreSQL gate are established by the review PRs' exact-commit CI jobs. Failures exceeding the existing five-minute full-suite limit through the remote port-forward remain recorded: no threshold was raised, no test skipped and no timeout counted as a pass; a successful focused run does not substitute for the full gate.
