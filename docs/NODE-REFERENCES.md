# 事务内文件引用 / Transaction-scoped file references
状态 / State: BIN-132 最小 SQL 投影切片，已实现并经 `-race` 单元、共享检查与真实 PostgreSQL 17.10 门禁验证；本页是公开规范来源。
Minimal SQL projection slice implemented and verified by `-race` unit tests, the shared check and a real PostgreSQL 17.10 gate; this page is the public canonical source.

## 范围与证据 / Scope and evidence
`internal/repository.FileReference`（ID + `Path` + `content.Metadata`）与 `internal/repository/postgres.Store`（`New(tx)`/`Create`/`Update`/`Lookup`）实现**文件**节点引用的最小 nodes 投影。对齐的目标静态事实（Artifactory 7.161.26 revision 86126900，WAR SHA-256 `9c2c1883…8c9f37`；storage-db 7.161.15 SHA-256 `7687e761…6c8164e9`；私有 javap 记录见[研究索引](RESEARCH-INDEX.md)）：
`internal/repository.FileReference` (ID + `Path` + `content.Metadata`) and `internal/repository/postgres.Store` (`New(tx)`/`Create`/`Update`/`Lookup`) implement a minimal **file**-node reference projection over nodes. Grounded target static facts (private javap notes; see the [research index](RESEARCH-INDEX.md)):

- `NodesDao.create` 是普通 INSERT（`createIfNotExists` 是另一方法）；泛型 `update` 按 `node_id` 更新且不改 `node_type`；`get` 键为 repo/parent/name，与输入 file/folder 无关。
  `NodesDao.create` is a plain INSERT (`createIfNotExists` is separate); the generic `update` keys on `node_id` and leaves `node_type`; `get` keys on repo/parent/name regardless of the input kind.
- `BaseDao.dotIfNullOrEmpty`/`emptyIfNullOrDot` 是**字面**空串↔'.' 边界，不是 Java-blank 折叠。
  `BaseDao.dotIfNullOrEmpty`/`emptyIfNullOrDot` form the **literal** empty↔'.' boundary, not a Java-blank collapse.
- 目标打包全新 `postgresql.sql`（SHA-256 `667a150c…dbf133cf` 行 23..53）含 `node_id` 主键、三元组唯一索引（`varchar_pattern_ops`）、`nodes.sha1_actual → binaries.sha1` 外键与 SHA1 索引；仅是打包全新模式，**未查询安装库实际模式**。
  The packaged fresh `postgresql.sql` (SHA-256 `667a150c…dbf133cf`, lines 23..53) carries the `node_id` PK, the tuple unique index (`varchar_pattern_ops`), the `nodes.sha1_actual → binaries.sha1` FK and the SHA1 index; that is the packaged fresh schema only — the **installed** target schema was never queried.
- 上游 `FileService.createFile` 另行调用 `PathValidator`；DAO 事务属上层，`RepositoryService` 先加 binary 再开节点事务，选定失败处理器可标记回滚。以上是静态/清单证据，不宣称目标数据库故障运行时对等。
  Upstream `FileService.createFile` applies `PathValidator` separately; the DAO transaction belongs to an upper layer, and `RepositoryService` adds the binary before the node transaction, with a selected failure handler that may mark rollback. These are static/inventory facts — no target DB-fault runtime parity is claimed.

## 契约 / Contract
- **调用方事务所有权**：`New(tx)` 拒绝 nil（固定文案），Store 不 Begin/Commit/Rollback/Ping/DDL/Close；调用方拥有事务、节点 ID 与生命周期。`Create`/`Update` 的**成功计数在调用方 Commit 前是临时的**（延迟约束下可返回 1,nil 而 Commit 失败、行不存在）。错误返回 0 与固定操作文案，`Unwrap` 原样保留原因（`errors.Is/As` 可达）。
  **Caller transaction ownership**: `New(tx)` rejects nil (fixed text) and the Store never begins/commits/rolls back/pings/DDLs/closes; the caller owns the transaction, node IDs and lifetime. Successful `Create`/`Update` counts stay **PROVISIONAL until the caller commits** (under a deferred constraint Create may return 1,nil while Commit fails and no row exists). Errors return 0 with a fixed operation text and `Unwrap` preserves the untouched cause (`errors.Is/As` reachable).
- `Create`：普通参数化 INSERT（`node_type=1`），返回受影响行数；无 ON CONFLICT/回读/重试。`Update`：仅更新可变投影列，`WHERE node_id AND node_type=1`；缺失 ID 返回 0,nil 绝不转创建。文件 Kind 守卫是**显式本地投影策略**（目标泛型 DAO 只按 ID 更新）。`Lookup`：按 repo/parent/name 查询并忽略输入 Kind；命中非文件行返回 `ErrNotFile`；缺失返回固定文案且 `errors.Is(err, sql.ErrNoRows)`；返回存储 ID、重构文件 `Path` 与元数据，无重算/回填。
  `Create`: an ordinary parameterized INSERT (`node_type=1`) returning the affected count; no ON CONFLICT/readback/retry. `Update`: mutable projection columns only, `WHERE node_id AND node_type=1`; a missing ID yields 0,nil and never a create. The file-kind guard is **explicit local projection policy** (the target generic DAO updates by ID only). `Lookup`: queries by repo/parent/name ignoring the input kind; a stored non-file row yields `ErrNotFile`; a miss yields the fixed text with `errors.Is(err, sql.ErrNoRows)`; it returns the stored ID, a reconstructed file `Path` and metadata with no recompute or backfill. 自 BIN-142 起，三个操作另携带 `FileReference.Metadata` 的七列元数据投影（Create nil=全 NULL；Update nil=不触碰/非 nil=同语句原子替换；Lookup 追加七列并做形状分类），语义与编解码见[文件元数据持久化](FILE-METADATA-PERSISTENCE.md)。
  Since BIN-142 the three operations also carry the seven-column metadata projection of `FileReference.Metadata` (Create nil = all NULL; Update nil = untouched / nonnil = atomic same-statement replacement; Lookup appends the seven columns and classifies the row shape), with semantics and codec in the [file-metadata persistence note](FILE-METADATA-PERSISTENCE.md).
- **SQL 边界**：空 parent/name（仅空串，Unicode 空白原样保留）写为 '.'；读 NULL/空/'.' 归一为空；parent 与 name 是独立列。`Content` 仅在**写入**时要求规范；`Lookup` 对存量行按原样返回——NULL MD5/SHA256 经 `sql.NullString` 映射为空（可为空投影），不回填。外键只证明 SHA-1 已在 binaries 登记，**不**证明跨校验和/长度一致或物理字节完整。
  **SQL boundary**: an empty parent/name (the empty string only; Unicode blanks are retained) writes '.'; reads normalize NULL/empty/'.' to empty; parent and name are separate columns. `Content` must be canonical on **writes** only; `Lookup` returns legacy rows as-is — NULL MD5/SHA256 map to empty via `sql.NullString` (possibly an empty projection), with no backfill. The FK proves only that the SHA-1 is registered in binaries — **not** cross-checksum/length agreement or physical byte integrity.
- **写前校验（本地策略，非目标对齐）**：ID>0、非零构造 `Path`、`IsFile` 且非根、字面 '.' parent/name 排除（避免与 SQL 点哨兵互为别名——本地规范画像）、`Path.Depth()` 上界（保留 `repository.ErrDepthExceeded`）、SHA-1/SHA-256/MD5 精确长度小写 ASCII 十六进制与 `Size>=0`（显式本地内容管道前置）。不做 Clean/TrimSpace/小写化/其他斜杠归一，也不实现臆测的 `PathValidator`。查询侧允许 folder Kind 与根查询。预取消的有效调用在任何事务访问前返回零值 + context 原因；错误文案有界且永不回显输入、SQL 或原因文本。
  **Pre-SQL write validation (local policy, not target parity)**: ID>0, a nonzero constructed `Path`, `IsFile` and non-root, literal '.' parent/name exclusion (avoiding aliasing with the SQL dot sentinel — a local canonical profile), the `Path.Depth()` bound (preserving `repository.ErrDepthExceeded`), exact-length lowercase ASCII hex SHA-1/SHA-256/MD5 with `Size>=0` (an explicit local content-pipeline precondition). No Clean/TrimSpace/lowercasing/other-slash normalization and no guessed `PathValidator`. Folder-kind and root queries stay permitted on lookup. Pre-canceled valid calls return zero values with the context cause before any transaction access; error texts are bounded and never echo input, SQL or cause text.

## 模式 / Schema
`schema.sql`（**现 v2**，embed 为 `SchemaSQL`）仅供可信全新引导/测试显式应用：v1 基础（`node_id` 主键、`node_type` 0/1、三个身份列（repo/node_path/node_name）`NOT NULL COLLATE "C"`（显式本地确定性排序策略）、`depth`、`bin_length` 与三个校验和列，三元组唯一索引（`varchar_pattern_ops`）+ SHA1 索引，`sha1_actual → binaries(sha1)` 外键无级联）上，BIN-142 新增七个可空无 DEFAULT 元数据列（created/modified/updated BIGINT、created_by/modified_by VARCHAR(64)、sha1_original/md5_original VARCHAR(1024)）与 `nodes_metadata_shape` CHECK，七列语义与受信任 v1→v2 升级/回退 SQL 见[文件元数据持久化](FILE-METADATA-PERSISTENCE.md)。**不是目标迁移/导入模式**；无自动 ID/父目录、删除/GC、属性/统计列——完整节点行留待后续切片。
`schema.sql` (**now v2**, embedded as `SchemaSQL`) is applied only by trusted fresh bootstrap/tests: over the v1 base (`node_id` PK, `node_type` 0/1, all three identity columns (repo/node_path/node_name) `NOT NULL COLLATE "C"` (explicit local deterministic collation policy), `depth`, `bin_length`, three checksum columns, the tuple unique index (`varchar_pattern_ops`) plus the SHA1 index, and the `sha1_actual → binaries(sha1)` FK without cascade), BIN-142 adds seven nullable no-DEFAULT metadata columns (created/modified/updated BIGINT, created_by/modified_by VARCHAR(64), sha1_original/md5_original VARCHAR(1024)) plus the `nodes_metadata_shape` CHECK, with the seven-column semantics and the trusted v1→v2 upgrade/downgrade SQL in the [file-metadata persistence note](FILE-METADATA-PERSISTENCE.md). It is **not** a target migration/import schema; no auto IDs/parents, deletion/GC, properties/stats — full node rows remain later slices.

## 验证 / Verification
单元（`-race`，仅不触库分支，dummy `&sql.Tx{}`）：nil 事务、非法 ID/Kind/根/点/校验和/大小先于 SQL 拒绝、1MiB 输入不出现在有界错误文本、深度哨兵、预取消、空↔点边界表。真实 PostgreSQL 17.10 门禁（复用既有夹具，12 组场景）：规范 Create/Lookup 与点哨兵、Kind 忽略、大小写/组件敏感键；未提交池外不可见、提交可见、回滚消失；重复元组/ID → SQLSTATE 23505 且中止事务不隐藏、调用方回滚保留原行；缺失 binary FK → 23503；Update 稳定 ID 换 SHA1 且两条 binary 保留、缺失 ID 0,nil 不插入；失败事务回滚保留旧引用与先前写入；延迟约束下 Create 返回 1,nil 而 Commit 失败且行不存在（临时计数）；原始 folder 行 Lookup `ErrNotFile`/同键冲突/Update 0 行不改 Kind；存量 NULL 校验和映射为空不变异；同步持锁事务 + 有限语句取消保留原因；真实 filestore + `binary.Service` 组合：binary 先提交、节点失败回滚保留字节与登记行、新读取器重试复用对象且新节点事务成功，无补偿。
Unit (`-race`, no-DB branches only, dummy `&sql.Tx{}`): nil tx; invalid ID/kind/root/dot/checksum/size rejected before SQL; a 1MiB input absent from bounded error text; the depth sentinel; pre-cancellation; the empty↔dot boundary table. Real PostgreSQL 17.10 gate (existing fixtures, 12 scenario groups): canonical Create/Lookup with the dot sentinel, kind-ignoring and case/component-sensitive keys; uncommitted invisible outside the pool, commit visible, rollback absent; duplicate tuple/ID → SQLSTATE 23505 with the aborted tx not hidden and caller rollback preserving the original; missing binary FK → 23503; Update keeping a stable ID while switching SHA1 with both binary rows retained and missing-ID 0,nil without insert; failed-transaction rollback preserving the old reference and earlier writes; a deferred constraint where Create returns 1,nil, Commit fails and no row exists (provisional counts); raw folder-row Lookup `ErrNotFile`/same-key conflict/Update zero rows without a kind change; legacy NULL checksums mapping empty without mutation; a synchronous lock holder with bounded statement cancellation preserving the cause; and the real filestore + `binary.Service` composition where the binary commits first, a node failure/rollback keeps bytes plus the registry row, and a fresh-reader retry reuses the object with a succeeding node transaction — no compensation.

调用方 Commit 遇到传输错误时，事务结局可能不确定；本适配器不确认提交结局，也不自动重试。`Unwrap` 原因仅供可信诊断，HTTP 与日志需按信任边界处理原因文本。
A transport error during the caller’s Commit can leave its outcome indeterminate; this adapter neither resolves that outcome nor retries. Unwrapped causes are for trusted diagnostics; HTTP and logging must filter cause text at the appropriate trust boundary.

Codex 对最终实现独立验证 21 项数据库场景，并以 8 个独立进程在同一路径屏障后竞争：1 个提交、7 个保留 SQLSTATE 23505，最终仅一条引用。另以真实 provider/登记服务验证节点失败后的字节与登记保留，以及新读取器重试的 inode 复用；新增永久回归固定路径键非空/C 排序和错误文案。
Codex independently verified 21 database scenarios and an 8-process barrier race for one path: one committed, seven retained SQLSTATE 23505, and exactly one reference remained. Real provider/registry composition also verified retention after node failure and same-inode reuse on a fresh-reader retry; permanent regressions pin non-null/C-collated keys and fixed error text.
